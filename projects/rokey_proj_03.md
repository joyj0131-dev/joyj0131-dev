# Project 03 — 디지털 트윈 기반 자율 발렛파킹 로봇 시스템

## 프로젝트 개요

입차·출차 전용 메카넘 로봇 4대가 차량 하부로 진입해 차량을 들어 올리고, 지정된 주차 슬롯까지 운반하는 디지털 트윈 기반 자율 발렛파킹 시스템입니다.

- 기간: 2026.07.15 ~ 2026.07.29
- 환경: Ubuntu 22.04, ROS 2 Humble, NVIDIA Isaac Sim 5.1
- 구분: 4인 팀 프로젝트
- 담당: 팀장 및 관제 알고리즘
- 원본 저장소: [Rokey_proj_03-Isaac-Sim-](https://github.com/joyj0131-dev/Rokey_proj_03-Isaac-Sim-/)

## 프로젝트 목표

- 메카넘 로봇 2대를 한 쌍으로 구성해 차량 하부 진입·리프트·운반 자동화
- 입차와 출차 전용 로봇쌍을 분리하고 관제에서 작업 요청 라우팅
- ArUco와 휠 오도메트리를 결합한 주차장 내 위치 추정
- Depth Camera 기반 차량 하부 정렬과 축 위치 검출
- LiDAR 기반 통로 장애물 및 주차 슬롯 점유 확인
- MySQL 기반 차량·작업·로봇·슬롯·안전 상태 관리
- 중앙 안전 상태에 따른 신규 작업 차단과 비상정지 복구


## 주요 문제 해결

### 1. 동일 차량의 작업 중복 생성

여러 요청이 동시에 접수되면 동일 차량에 대한 활성 작업 검사가 끝나기 전에 다음 요청이 들어와 중복 작업이 만들어질 수 있었습니다.

작업 접수 구간을 Lock으로 직렬화하고, Lock 내부에서 차량별 활성 작업과 중앙 안전 상태를 다시 검사한 뒤 작업을 생성하도록 구성했습니다. 안전 상태가 `NORMAL`이 아니면 신규 요청을 거부해 비상 상황에서 새로운 미션이 시작되지 않도록 했습니다.

### 2. 로봇·구역·주차 슬롯의 동시 점유

입차와 출차 요청이 겹치면 여러 로봇이 같은 이동 구역이나 슬롯을 동시에 확보할 수 있었습니다. 필요한 구역 자원을 정해진 순서로 요청하고, 일부 자원만 획득한 경우 확보한 자원을 모두 반납하는 DB Zone Lock 정책을 적용했습니다.

빈 슬롯은 작업 실행 전에 `RESERVED` 상태로 예약하고, 미션 완료 시 `OCCUPIED`로 전환했습니다. 작업이 실패하거나 취소되면 로봇·슬롯·구역 상태를 복구해 다음 요청이 잘못된 점유 상태를 이어받지 않도록 했습니다.

### 3. 비동기 로봇 작업과 관제 상태의 불일치

ROS 2 Action은 실행 시간이 길고 성공·실패 결과가 비동기로 도착하므로, 요청 접수 직후 DB 상태만 변경하면 실제 로봇 상태와 관제 화면이 달라질 수 있었습니다.

Service 요청 처리, Action goal 전송, 결과 callback과 DB 상태 갱신을 연결했습니다. Action 완료 여부에 따라 작업 결과와 로봇·슬롯 상태를 갱신하고, 로봇 4대의 Odometry를 관제 좌표계로 변환해 DB와 화면에 반영했습니다.

## 중앙 안전 상태

```text
NORMAL
→ 비상정지
→ STOPPED_LATCHED
→ 현장 점검 및 관제 확인
→ READY_FOR_OPERATION
→ 운영 복귀 승인
→ NORMAL
```

- 안전 상태가 `NORMAL`이 아니면 신규 입·출차 요청 거부
- 비상정지 이후 현장 점검과 운영 승인을 분리
- 안전 상태를 MySQL에 저장해 노드 재기동 후에도 유지
- 작업 실패 시 로봇과 운영 자원 상태 복구

## 추후 개발 사항 — SLAM·Nav2 혼합 구조

현재 ArUco·휠 오도메트리 기반 주행을 확장해 다음 구조를 학습하고 적용할 계획입니다.

- SLAM을 이용한 주차장 지도 생성
- Nav2 기반 전역 경로 계획
- Costmap 기반 장애물 반영과 회피
- 주차장 전역 이동에는 SLAM·Nav2 적용
- 도킹과 차량 하부 진입·정렬에는 ArUco·Depth 유지
- 전역 자율주행과 근거리 정밀 제어를 결합한 혼합 구조 검증

> SLAM·Nav2 구조는 현재 프로젝트와 저장소에 구현되지 않았으며, Isaac Sim에서 성능 검증된 결과도 아닙니다. 추후 학습·개발·검증할 개선 계획입니다.
