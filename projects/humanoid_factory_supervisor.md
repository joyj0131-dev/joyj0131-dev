# Project 05 — 공장 고장 복구 휴머노이드 (Humanoid Factory Supervisor)

## 프로젝트 개요

자동화 공장 라인에서 고장이 나면 휴머노이드가 고장 난 라인까지 걸어가, 몸 전체와 양손으로 부품을 복구하고 생산을 재가동시키는 시뮬레이션 프로젝트입니다. 정상 생산은 자동화 팔과 컨베이어가, 예외 상황 복구는 휴머노이드가 맡는 구조입니다.

|---|---|
| 기간 | 2026.08.28 ~ 진행 중 |
| 구성 | 개인 프로젝트 |
| 환경 | MuJoCo 3.12 · Python · Unitree G1 + Sharpa Wave 5지 양손 · NumPy/SciPy · PyTorch(PPO) |
| 담당 | 전체 설계·구현·실험·검증 |

- 코드 저장소: [Humanoid_Factory_Supervisor](https://github.com/joyj0131-dev/Humanoid_Factory_Supervisor) (최신 작업은 `phase5/factory-environment` 브랜치)
- 시연 영상: 업로드 예정

## 프로젝트 목표

- 고장이 날 수 있는 2라인 공장 시뮬레이션과, 복구 결과를 물리량으로 판정하는 작업 관리자 구축
- 고장 난 라인까지 보행 접근 후 서서 또는 웅크려서 양손으로 부품 파지
- 바닥에 떨어진 부품을 테이블 정위치에 놓고 손을 회수한 뒤 라인 재가동까지 전체 흐름 완성
- 블록 위치·무게가 바뀌어도 성공하는 제어기(강건성)와, 그 위에서 강화학습으로 성능을 개선하는 구조 검증

## 전체 작동 흐름

```text
자동화 팔이 부품을 바닥에 떨어뜨림(고장 주입)
→ Task Manager가 라인 정지·복구 요청 → 휴머노이드 수락
→ 통로 접근·제자리 회전·정밀 접근(사전학습 보행 정책)
→ 무릎을 벌리고 웅크려 손가락 끝 패드로 블록 파지
→ 블록을 든 채 기립 → 테이블 위로 이송·안착
→ 손 회수 → 완료 신호
→ Task Manager가 위치·기울기·회전·접촉·정지를 50틱 연속 검사
→ 통과 시 자동화 팔·컨베이어 재가동
```

## 주요 문제 해결

### 1. 한 장면에서만 통하는 "아슬아슬한 성공"

바닥 → 테이블 → 재가동 전체 흐름이 기본 장면에서 처음 성공했지만, 손 위치를 0.0015 mm만 바꾸거나 블록 무게를 0.0001 % 바꿔도 일어서는 중 블록을 놓쳤습니다. 강화학습이 15번 시도 중 한 번도 성공하지 못한 원인을 조사하다가 발견했습니다. 이후 블록 위치·무게·손 흔들림을 바꾼 조건 묶음을 만들고, 실패할 때마다 같은 조건을 다시 돌려 힘·자세를 기록해 원인을 하나씩 제거했습니다.

- 개발 조건 15가지: 1/15 → 14/15
- 튜닝에 쓰지 않은 검증 조건 12가지: 9/12 → 12/12

### 2. 손을 펴는 순간 블록이 돌아가는 문제

가장 잦은 실패는 블록을 정확히 내려놓고도 판정에서 떨어지는 경우였습니다. 계측해 보니, 내려놓는 동안 테이블과 블록이 받쳐 주던 팔이 손을 펴는 순간 3.7 cm 처지고, 엄지 끝이 블록 윗모서리를 4~5 N으로 눌러 20~25° 기울였다가 떨어뜨리고 있었습니다. 손을 펴는 동안 실제 손 높이를 재서 유지하고, 손 벌림을 3.5 cm에서 6 cm로 늘려 해결했습니다.

### 3. 일어설 때 손목 관절 한계

손가락을 아래로 향한 채 블록을 가슴 높이로 들면 손목이 관절 한계에 닿아 블록을 놓쳤습니다. 들어 올리는 구간에서 손을 굴려 손가락이 앞을 향하게 하고(손목 여유 0.14 → 0.35~0.42 rad), 테이블 위로 내려가는 구간에서 되돌리도록 했습니다. 되돌리는 시점을 앞으로 뻗는 구간에서 내려가는 구간으로 옮긴 것만으로 실패하던 4개 조건이 성공했습니다.

### 4. 테이블 가까이 떨어진 블록

블록이 테이블 앞면에서 몇 cm 안쪽에 떨어지면 웅크릴 때 몸통이 테이블 모서리에 30~105 N으로 부딪혔습니다. 블록과 테이블 사이 거리에 따라 서는 위치를 두 단계로 물리고, 멀리 서서 집을 때 팔이 처지는 만큼 첫 들어 올리기를 실제 높이 기준으로 보정했습니다.

### 5. 강화학습이 이미 잘하는 제어기를 오히려 망치는 문제

| 회차 | 바꾼 것 | 학습 전 → 학습 후 |
|---|---|---|
| 1차 | 성공 위주 보상 | 5/8 → 5/8 |
| 2차 | 개입 구간 축소, 내려놓기 품질 점수 | 11/16 → 13/16(중간) → 12/16 |
| 4차 | 진행 속도 행동 추가, 시간·충돌 힘·흔들림 보상 | 15/16 → 12/16 |

시도 한 번이 8~9분이라 하룻밤 50~100번이 한계였고, 1~2 mm 차이에도 결과가 갈리는 동작에서 탐색 잡음이 성공률을 떨어뜨렸습니다. 이를 근거로 신뢰성은 제어기로 만들고, 최적화는 "성공률이 떨어지면 채택하지 않는" 저차원 정책 탐색으로 하는 방향으로 전환했습니다.

## 한계

- 시뮬레이션 전용이며 실물 로봇 검증은 없습니다.
- 무작위 100회 기준 성공률은 80 %입니다. 블록이 테이블 앞면 3.3~5.5 cm에 떨어진 경우가 가장 약합니다(6/14).
- 강화학습으로 성공률을 올리지는 못했습니다. 개선은 제어기 수정에서 나왔습니다.
- 블록을 든 채 걷기, 크게 회전된 블록 파지, 어깨–몸통 자기 접촉은 미해결입니다.
- 보행은 외부 사전학습 정책을 사용합니다.

## 추후 개발 사항

1. 무작위 100회에서 나온 실패 유형(일어서며 손을 굴리는 구간의 미끄러짐 등) 제거 — 목표 98/100 이상
2. 단계별 진행 속도 몇 개만 조정하는 정책 탐색(CMA-ES 등)으로 시간·충돌 최적화, 성공률 비하락 조건
3. 같은 무작위 100회로 재측정해 "성공률 유지 + 효율 개선" 확인

## 회고

- 한 번의 성공은 성공이 아니며, 조건을 바꾼 반복 측정과 튜닝에 쓰지 않은 검증 조건이 필요하다는 점
- 실패를 재현해 힘·자세를 기록하면 추측으로는 찾지 못한 원인(손 처짐, 엄지 접촉)이 보인다는 점
- 강화학습은 표본이 적고 동작이 예민한 문제에서 기존 제어기를 해칠 수 있으며, 역할(신뢰성 vs 최적화)을 나눠야 한다는 점
- 틀린 결론과 버린 방법도 기록해야 같은 실수를 반복하지 않는다는 점
